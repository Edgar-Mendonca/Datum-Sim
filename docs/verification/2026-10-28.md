## Window

- UI checks (`tests_ui/run.cjs`, 30 in all, 3 new): a motor block shows its port names; a motor offers its typical ratings; choosing one sends every value as one undoable edit.
- In the real app under Xvfb: the direct-on-line start and the field-oriented control examples run with live scopes; the Inspector shows the typical ratings and the preset values.

## Bugs these checks found

- The preset formatter dropped trailing zeros from whole numbers (Nr = 50 became 5, 220 Ω became 22 Ω). The stepper example lost steps because of it; fixed, and the round-trip test above guards it.
- A zero-crossing function that landed exactly on zero at the end of a located step lost its sign, so the next crossing was missed (the switched inverter's mean came out 75 V instead of 110 V). The solver now keeps the last non-zero sign.

## Not verified

- Power balance (electrical input = mechanical output + losses) for each machine, and locked-rotor current against a measured machine: planned.
- The typical ratings are typical per-unit values, not data of a real machine; they give realistic behaviour, not a particular motor.
- Saturation, iron losses, skin effect beyond the double cage, and commutation ripple in the BLDC are not modelled.
- Not yet run on Windows (CI builds and tests there).
