## Hardening (FAMILY §11, crates/core/src/hardening.rs)

- Failed edits (13 kinds, including a batch that fails half way) leave the model exactly as it was, with nothing to undo.
- 60 random models (2 000 in a longer local run) of random blocks, wires, parameters, groupings, deletions, undos and redos: no panic, invariants hold (unique ids, no dangling wires, one wire per input, ports exist), every compiled model runs, every file round-trips. The random runs found two real crashes on their first run (signal widths growing forever through a Mux in a loop; a Sum whose signs used `*`), both fixed.
- Damaged files: cut at every 37th byte, 300 garbled copies, subsystems nested 100 deep, wrong types, a newer format: no panic; damaged ids and wires are repaired.
- Speed gate, 500 blocks in a chain: routing 73 ms, compile and run 44 ms (release build; limit 1.5 s, 8 s in debug).

## The window (tests_ui/run.cjs) and the real app

- 22 UI checks pass against the engine's real output (see the file).
- Checked in the real app on Linux (Xvfb): File page, every example, running with live scopes, selecting, the inspector, subsystems, Bode through the Python engine, building a model by drag and drop and wiring it, dark theme. Three bugs found this way were fixed and each has a UI check.
